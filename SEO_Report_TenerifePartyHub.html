Problemas Críticos

1. SCHEMA.ORG COMPLETAMENTE AUSENTE

No hay ningún dato estructurado en todo el sitio. Para un event planner, Schema tipo EventPlanner, LocalBusiness o Service es fundamental para aparecer en búsquedas locales y rich snippets.

Impacto: Invisible para búsquedas enriquecidas. Sin panel de conocimiento en Google. Sin posibilidad de mostrar servicios, precios o reseñas en los resultados.

Solución:

<script type="application/ld+json"> { "@context": "https://schema.org", "@type": "EventPlanner", "name": "Tenerife Party Hub", "url": "https://tenerifepartyhub.com", "description": "Luxury event planning and party services in Tenerife. Villa parties, boat parties, VIP experiences.", "address": { "@type": "PostalAddress", "addressLocality": "Tenerife", "addressRegion": "Canary Islands", "addressCountry": "ES" }, "areaServed": "Tenerife", "makesOffer": [ { "@type": "Offer", "itemOffered": { "@type": "Service", "name": "Villa Party Planning" } }, { "@type": "Offer", "itemOffered": { "@type": "Service", "name": "Boat Party Organization" } } ] } </script>

2. NAP (NOMBRE, DIRECCIÓN, TELÉFONO) AUSENTE

No se encontró información de contacto NAP en ninguna página del sitio. No hay dirección física, número de teléfono ni email visible. Para un negocio local que opera en Tenerife, esto es devastador para el SEO local.

Impacto: Google no puede verificar la legitimidad del negocio. Imposible aparecer en Google Maps o Local Pack. Los clientes potenciales no tienen forma de contactar directamente.

Solución: Añadir footer con dirección, teléfono, email y WhatsApp en todas las páginas. Crear página de contacto dedicada con formulario + mapa.

3. HOMEPAGE EN URL NO OPTIMIZADA

La homepage se sirve desde /en/home-en/ en lugar de la raíz del dominio (/). Esto diluye la autoridad SEO de la página principal y crea una estructura de URLs confusa.

Impacto: La autoridad del dominio no se concentra en la homepage. Los backlinks a la raíz no benefician la página principal real.

Solución: Configurar WordPress para que la homepage se sirva desde / (en inglés) y /es/ (en español). Implementar redirect 301 de /en/home-en/ a /.

4. POSTS PLACEHOLDER INDEXADOS

Se detectaron posts de WordPress por defecto que están publicados e indexables:

  • /hello-world/ - Post por defecto de WordPress nunca eliminado
  • /scheda-tipo-attivita/ - Plantilla de actividad en italiano (parece del setup inicial)

Impacto: Google indexa contenido vacío/irrelevante. Señal de sitio descuidado que reduce E-E-A-T.

Solución: Eliminar inmediatamente estos posts o añadir noindex.

5. PÁGINA PRIVADA DE CLIENTE EXPUESTA PÚBLICAMENTE

La URL /es/cristina-bday/ aparece en el sitemap y es accesible públicamente. Parece ser una página de planificación para el cumpleaños de una clienta llamada Cristina.

Impacto: Problema de privacidad del cliente. Contenido irrelevante indexado. Vulnerabilidad de datos personales.

Solución: Proteger con contraseña, hacer privada en WordPress, o eliminar del sitemap y añadir noindex, nofollow.

6. CSS INLINE 150KB+ POR PÁGINA (RENDIMIENTO)

Cada página carga más de 150KB de CSS inline generado por Elementor. Esto se suma al JS pesado del page builder, resultando en tiempos de carga excesivos.

Impacto: Core Web Vitals penalizados (LCP, FCP altos). Google prioriza sitios rápidos en mobile-first indexing. Usuarios en móvil con conexión lenta abandonan.

Solución: Activar "Improved CSS Loading" en Elementor > Settings > Experiments. Usar plugin de cache (WP Rocket, LiteSpeed Cache). Minificar CSS.

7. WP-SITEMAP-USERS EXPONE USERNAMES

El endpoint /wp-sitemap-users-1.xml está accesible y expone los nombres de usuario de los autores de WordPress. Esto es un riesgo de seguridad que facilita ataques de fuerza bruta.

Solución: Desactivar el sitemap de usuarios con el siguiente código en functions.php:

add_filter('wp_sitemaps_add_provider', function($provider, $name) { if ('users' === $name) return false; return $provider; }, 10, 2);

Problemas Adicionales

1. GOOGLE MY BUSINESS NO DETECTADO

No se encontró perfil de Google Business Profile vinculado al sitio. Para un negocio local de eventos en Tenerife, GMB es esencial para aparecer en búsquedas "near me" y Google Maps.

Solución: Crear y verificar perfil GMB con fotos de eventos, horarios, servicios y link al sitio.

2. META DESCRIPTIONS PROBABLEMENTE AUTO-GENERADAS

Las meta descriptions parecen ser extractos automáticos del contenido de la página en lugar de descriptions optimizadas manualmente con keywords y CTAs.

Solución: Instalar Yoast/RankMath y escribir meta descriptions únicas para cada página con keywords target y call-to-action.

3. SIN BLOG / CONTENT MARKETING

Con solo 22 páginas (incluyendo placeholder), no hay estrategia de contenido. Sin blog, es imposible posicionar para keywords informacionales como "best party venues tenerife" o "how to plan a villa party".

Solución: Crear blog con guías: "Top 10 Villa Party Venues in Tenerife", "How to Plan a Luxury Birthday in Tenerife", "Best Boat Party Ideas".

4. SIN GOOGLE ANALYTICS NI TRACKING

No se detectó GA4 ni ningún sistema de analytics. Sin datos de comportamiento de usuarios no es posible optimizar conversiones ni medir el ROI.

5. SIN RESEÑAS / TESTIMONIOS CON SCHEMA

Para un servicio de alto valor (eventos luxury), las reseñas son críticas. No hay sección de testimonios con Schema Review que permita mostrar estrellas en Google.

6. ESTRUCTURA BILINGÜE INCOMPLETA

El sitio tiene estructura /es/ y /en/ pero no queda claro si todas las páginas están disponibles en ambos idiomas. Faltan hreflang tags para indicar a Google la relación entre versiones.

PRIORITÀ 6: Sitemap - Date Invalide

Problema: Timestamp Anno -0001 su Pagine Sistema

PAGINE CON DATE INVALIDE
# ❌ SITEMAP ENTRIES CON ANNO -0001: /book-appointment/ -0001-11-30T00:49:56+00:49 /my-bookings/ -0001-11-30T00:49:56+00:49 /thank-you/ -0001-11-30T00:49:56+00:49 /cancel-appointment/ -0001-11-30T00:49:56+00:49 /cancel-payment/ -0001-11-30T00:49:56+00:49 /appointment-cancellation-confirmation/ -0001-11-30T00:49:56+00:49 /appointment-reschedule/ -0001-11-30T00:49:56+00:49

Causa probabile:

  • Pagine create da plugin BookingPress senza data pubblicazione
  • WordPress restituisce timestamp default (01/01/0000)

Impatto:

  • ⚠️ Sitemap tecnicamente invalido
  • ⚠️ Google Search Console potrebbe segnalare errori
  • ⚠️ Crawler confusi su freshness contenuti
SOLUZIONE 1: Escludere Pagine Sistema dal Sitemap
# WordPress wp-config.php o functions.php // Escludere pagine BookingPress dal sitemap add_filter('wp_sitemaps_posts_query_args', function($args, $post_type) { if ($post_type === 'page') { $args['post__not_in'] = [ 123, // ID book-appointment 124, // ID my-bookings 125, // ID thank-you // ... altri ID pagine sistema ]; } return $args; }, 10, 2);
SOLUZIONE 2: Forzare Data Valida
// Impostare data pubblicazione manuale su pagine sistema // WordPress Admin → Pages → Edit → Publish box → Published on: [data corretta] // Oppure via SQL: UPDATE wp_posts SET post_date = '2025-08-01 12:00:00', post_date_gmt = '2025-08-01 10:00:00' WHERE ID IN (123, 124, 125, ...);
ACTION ITEMS
  • Identificare ID pagine con date invalide
  • OPZIONE A: Escludere dal sitemap (pagine solo per utenti loggati)
  • OPZIONE B: Forzare date valide
  • Rigenerare sitemap
  • Verificare in Google Search Console (Coverage report)

RACCOMANDAZIONE: Escludere pagine sistema dal sitemap (non devono essere indicizzate)

12. Performance & Core Web Vitals

Osservazioni:

  • Lazy loading presente ✅
  • Multipli tracking scripts (GA4, FB Pixel, Metricool)
  • WordPress con Astra theme (generalmente veloce)
  • WooCommerce e BookingPress (possibile overhead)
ACTION REQUIRED

Test con Google PageSpeed Insights:

  • Mobile score (target: >90)
  • Desktop score (target: >95)
  • Largest Contentful Paint (LCP): <2.5s
  • First Input Delay (FID): <100ms
  • Cumulative Layout Shift (CLS): <0.1
OTTIMIZZAZIONI RACCOMANDATE

1. Immagini

  • Convertire a WebP (risparmio 30-40%)
  • Implementare srcset responsive
  • Dimensioni corrette (no 4K per thumbnail)
  • Compressione aggressiva (TinyPNG, ShortPixel)

2. JavaScript/CSS

# WordPress plugins raccomandati: - WP Rocket (caching + minify + defer JS) - Autoptimize (aggregare CSS/JS) - Asset CleanUp (disabilitare plugin non usati per pagina) # Configurazioni critiche: ✓ Minify HTML/CSS/JS ✓ Defer non-critical JavaScript ✓ Remove query strings from static resources ✓ Lazy load images + iframes ✓ Browser caching (1 year for static assets)

3. Tracking Scripts

# Caricare tracking scripts via Google Tag Manager (async) # Delay Facebook Pixel fino a user interaction # Implementare consent-based loading (GDPR + performance)

4. CDN

  • Implementare Cloudflare (free tier sufficiente)
  • Servire immagini da CDN
  • Abilitare Brotli compression

ROI ATTESO: +10-15% ranking (Google considera performance), migliore UX
